# 柏维酒店日报生成技能

## 概述
为柏维酒店郑州店前台员工生成每日工作总结，每天1条服务案例，发到微信群"小柏店销群"。

### 核心规则

### 班次规则（重要）
- **早班日报**（触发词"早班日报"）：写**2条**事件，**带标题**（当天日期+柏维郑州店店销岗）
- **晚班日报**（触发词"晚班日报"）：写**1条**事件，**不带标题**
- **默认**（触发词"写日报"等）：写**3条**事件，**带标题**（当天日期+柏维郑州店店销岗）

### 交互规则（重要）
- **不问名字、不问人数**，直接出稿，标题只写当天日期+柏维郑州店店销岗，不加姓名
- 标题固定写"店销岗"，日期填当天实际日期，不要占位符
- 用户说"写一条"就是一条，不要自作主张写多条
- 用户说"换一个"就是只换那一条，不重写全部

### 写作风格
- **第一人称叙述**，像员工口述，不是AI总结
- **朴实真诚**的语气，允许口语化表达（"我说不客气"、"先生您看"）
- 每条150-250字
- 结尾通常有客人感谢/好评的反馈
- 每条自成一段，包含：起因→行动→结果/反馈
- 不用编号列表、不用emoji、不用小标题

### 禁止事项（雷区）
- ❌ 不能写"空调遥控器"、"换电池" — 酒店用中央空调
- ❌ 不能写"自助洗衣房" — 洗衣房在负1楼，员工代洗，不对客人开放
- ❌ 不能写不存在的设施（无健身房、无游泳池）
- ❌ 房号不能含4（无X04、X14），最大号18
- ❌ 1楼房号从106起（101-105为公共区域）
- ❌ 不能编造不存在的房型

### 格式模板（单条版，默认）
```
当天日期号柏维郑州店店销岗
今日完成工作总结

1.（服务场景叙述，150-250字）
```

### 格式模板（多条版，用户明确要求时）
```
当天日期号柏维郑州店店销岗
今日完成工作总结

1.（服务场景叙述，150-250字）

2.（服务场景叙述，150-250字）

3.（服务场景叙述，150-250字）
```

### 生成前须知（不要问用户）
- **人数**：默认只写1个人，不要问"写几个人的"
## 使用方式

用户说"帮我编日报"/"帮我写条日报"等，按以下步骤执行。

### 默认行为（重要）
- **默认生成 1 条**（1个场景），不是3条。除非用户明确说"编X个人的"才按人数生成多条。
- **不问姓名、不问人数**。姓名处留 `________（姓名）` 占位，让用户自己填。
- 用户说"换一个"时，只替换那一条，重新抽场景生成。

### 生成流程（3个文件）
1. 读取 `references/voice-samples.md`（语气参考，固定大小）
2. 读取 `references/scenario-library.md`（50+场景类型）
3. 读取 `references/recent-log.md`（近期记录，去重用）
4. **不读取** real-examples.md（太大，不需要）

### 去重规则
- 查 recent-log.md，同一人的场景类型编号不能与最近7天内重复
- 房号不能与最近7天已用的重复
- 生成完毕后，把本次记录追加到 recent-log.md
- recent-log.md 超过30天的记录删除

### 生成步骤
1. 直接生成，不问日期/人数/姓名（日期用当天）
2. 从场景库中抽取1个**场景**（避开近期已用类型）
3. 分配房号（遵守编号规则，避开近期已用房号）
4. 参考语气范文的风格，用员工口吻编写，150-250字
5. 追加生成记录到 recent-log.md

## 日常素材收集

用户会每天分享各门店真实日报，收到后：
1. **提炼新场景**：发现场景库中没有的类型 → 补充到 scenario-library.md
2. **更新语气范文**：如果发现更好的语气范例 → 替换 voice-samples.md 中较弱的范文
3. **原文归档**：提炼版追加到 real-examples.md（仅归档，生成时不读取）
4. **不需要**读取 real-examples.md 来生成日报

## 验证清单
生成后自查：
- [ ] 房号不含4尾号，不超过18，楼层1-7（最高7楼，无8楼）
- [ ] 4楼也有客房，不能写"跳过4楼"或"没有4楼"
- [ ] 房型名称准确（6种之一）
- [ ] 无中央空调遥控器相关描述
- [ ] 未提及自助洗衣/健身房等不存在的设施
- [ ] 周边推荐只涉及：曼哈顿广场、紫金山公园、地铁1号线
- [ ] 退房时间准确：会员3点，中介1点（可延至2点）
- [ ] 语气自然，不像AI生成
